# WhatsApp Feasibility (§3)

Classifies each capability area §3 requires covering, against the **official
WhatsApp Business Platform Cloud API** only — never WhatsApp Web automation,
unofficial resellers, or browser-session hijacking (§3's non-negotiable rule).
Verified via Meta's own developer documentation
(`developers.facebook.com/documentation/business-messaging/whatsapp/...`) as
of 2026-08-20, cross-checked against what this codebase already implements
(`src/lib/whatsapp/meta-api.ts`) as evidence of working integration, not
memory. Where a third-party source (WhatsApp API reseller blogs, unofficial
wrapper vendors) contradicted Meta's own docs, Meta's docs won — several of
those resellers market **unofficial** automation as if it were part of the
Cloud API, which §3 explicitly forbids relying on.

Legend: `SUPPORTED` / `PARTIALLY SUPPORTED` / `NOT SUPPORTED` / `REQUIRES CONFIGURATION`.

## Messaging limit tier (§8)

Meta exposes the current tier via `GET /{phone_number_id}?fields=whatsapp_business_manager_messaging_limit`
(the older `messaging_limit_tier` field, e.g. `"TIER_250"`, still works but is
documented as deprecated in favor of the portfolio-level field). Documented
tiers: 250 → 2,000 → 10,000 → 100,000 → Unlimited, scaling automatically once
quality stays high and at least half the current limit is used within 7 days
— matching §8's description. Some 2026-era sources report Meta consolidating
limits at the **Business Portfolio** level (shared across every phone number
in the portfolio) and collapsing the 2K/10K tiers in favor of jumping straight
to 100K after verification; this is exactly the kind of "don't encode the
older tier scheme" churn §8 warns about, so this app does not hardcode any
tier list — it stores and displays whatever string Meta's API actually
returns, and renders `Unknown` (§2) when the field can't be fetched (no
config, API error, or a not-yet-verified account). See `docs/IMPLEMENTATION_PLAN.md`
Phase 8 for where this is wired (Settings + Announcements headroom display).

## What "build the abstraction anyway" means here

Per §3: where Meta doesn't support something Rimula's spec envisioned
(synthesized voice notes, AI-assisted translation — both dropped for Phase 8,
see IMPLEMENTATION_PLAN), the existing manual/BA-driven path already _is_ the
wired alternative, not a stub waiting for a provider. Where Meta _does_
support something but this account lacks the credentials (catalogue), the
abstraction is built and stubbed, not skipped.
