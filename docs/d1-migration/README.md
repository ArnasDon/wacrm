# Supabase → Cloudflare D1 migration

Staged migration off Supabase onto an all-Cloudflare stack. Work happens
on `feat/d1-migration`; each phase ends at a gate that must pass before
the next begins.

| Phase | Scope | Status |
| --- | --- | --- |
| 1 | Schema port to SQLite + Drizzle tooling | **done** |
| 2 | Better Auth cutover | not started |
| 3 | Data-access layer + tenant guards | not started |
| 4 | Durable Objects, R2, Vectorize + FTS5 | not started |
| 5 | Workers runtime + deploy | not started |

Decisions: Better Auth for auth, Durable Objects for realtime,
Vectorize + FTS5 for AI search, R2 for media.

**Nothing here is wired into the running app yet.** Phase 1 adds a
parallel schema and its tooling; `src/` still talks to Supabase, the
app still deploys from the Dockerfile, and `supabase/migrations/`
remains the live schema until Phase 3 cuts over.

## Phase 1 — what landed

- `src/lib/db/schema/` — 36 domain tables plus Better Auth's four,
  as Drizzle SQLite definitions.
- `drizzle/0000_initial_schema.sql` — generated DDL: 40 tables,
  58 indexes.
- `drizzle/0001_fts5_and_self_fks.sql` — hand-written: the FTS5 virtual
  table and its sync triggers, which Drizzle cannot express.
- `docs/d1-migration/postgres-function-inventory.md` — where each of the
  28 Postgres functions goes.
- `scripts/seed-d1.ts` — the gate. Seeds a full account and asserts
  seven schema behaviours.

### Gate result

```
PASS  contact reads back under its account
PASS  timestamp round-trips as a Date
PASS  json array column round-trips
PASS  boolean round-trips
PASS  reply_to_message_id points at a real message
PASS  fts5 index populated by trigger
PASS  CHECK constraint rejects an invalid status
```

Typecheck is unchanged from `main` (241 pre-existing errors on both —
the port introduces none).

## Setup

```bash
npx wrangler d1 create wacrm          # then paste the id into wrangler.jsonc
npm run db:migrate:local              # apply both migrations
npm run db:seed                       # boots a worker on :8788
curl http://localhost:8788/           # runs the seed + checks
```

`npm run db:reset:local` wipes the local database if you need to start
over. `npm run db:generate` regenerates DDL after a schema edit.

## Type mapping

| Postgres | SQLite / D1 | Note |
| --- | --- | --- |
| `UUID DEFAULT uuid_generate_v4()` | `TEXT` | Generated by `crypto.randomUUID()` in app code. The SQLite-side default is a `randomblob` fallback for writers that forget. |
| `TIMESTAMPTZ` | `INTEGER` epoch ms | Drizzle's `timestamp_ms` mode; app code still sees `Date`. |
| `JSONB` | `TEXT` | Drizzle `{ mode: 'json' }`. SQLite JSON1 functions work on it. |
| `BOOLEAN` | `INTEGER` 0/1 | Drizzle boolean mode. |
| `TEXT[]` | `TEXT` JSON array | `'x' = ANY(col)` becomes `json_each` or an in-memory check. |
| `NUMERIC(12,2)` | `INTEGER` minor units | **Behaviour change** — see below. |
| `DATE` | `TEXT` ISO `YYYY-MM-DD` | No time component intended. |
| `ENUM` | `TEXT` + CHECK | Plus a TS union so the type stays closed. |
| `tsvector` | FTS5 virtual table | Ranking sign flips — see below. |
| `vector(1536)` | Vectorize (outside D1) | Cannot be joined; query separately by id. |

### Deliberate behaviour changes

Three places where the port is not a faithful translation, each a
decision rather than an oversight:

1. **`deals.value` → `deals.value_minor`.** Postgres stored
   `NUMERIC(12,2)`; SQLite has no exact-decimal type and `REAL` would
   introduce float error on money. Values are now an integer count of
   minor units. **Any data migration must multiply existing values by
   100**, and app code must format at the boundary.

2. **Two self-FKs are not enforced by the database.**
   `messages.reply_to_message_id` and `automation_steps.parent_step_id`
   reference their own tables; Drizzle cannot declare that inline and
   SQLite cannot add a constraint after the fact. Both are enforced in
   the access layer, and both delete paths must clear the reference —
   Postgres had `ON DELETE CASCADE` doing it. Reasoning is in
   `0001_fts5_and_self_fks.sql`.

3. **FTS5 `bm25()` ranks in the opposite direction to `ts_rank`.**
   More-negative is a better match. Any hybrid scoring that merges
   lexical and semantic results must normalize before combining, or the
   ranking silently inverts.

### Things that stopped being free

RLS, atomic multi-step writes, and cross-store consistency were all
guaranteed by Postgres and now are not:

- **Isolation is application code.** 155 policies became one
  `assertMember()` call per access-layer entry point. A missed
  `account_id` filter is a cross-tenant leak with no database backstop —
  Phase 3's isolation tests exist for exactly this.
- **D1 has no interactive transactions.** `db.batch()` commits
  atomically but cannot read-branch-write. Every multi-step Postgres
  function had to be restructured; see the function inventory.
- **Vectorize and D1 do not share a transaction.** A chunk can land in
  one and not the other, so `ai_knowledge_chunks.vectorized_at` records
  whether the vector upsert succeeded and the reindex job repairs the
  gap.

## Not yet addressed

**Migrating existing production data is out of scope for Phase 1** and
is not covered by any phase in the current plan. It needs its own
design: type coercion for every UUID / JSON / timestamp / array column,
the `value_minor` conversion above, contact and conversation
deduplication run *before* import (the unique indexes reject duplicates
the Postgres repair functions used to collapse), and a password-reset
path for every existing user, since password hashes do not transfer
between auth systems.

If this instance has live accounts, scope that work before Phase 2.
