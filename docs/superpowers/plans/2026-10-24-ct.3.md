# CT.3 · Contrato de módulos — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** publicar la interfaz `I3` como código verificable: el contrato de un módulo (interruptor, migraciones con prefijo propio, esquema zod de su config y punto de enganche en el flujo de entrada), un stub derivado del contrato y las pruebas CDC de ASG y VIS contra ese stub.

**Architecture:** un módulo de contrato (`contracts/mod/module.ts`) sin dependencias del repo (solo zod y el tipo `ModuloSwitch` de I1), con `definirModulo` (valida nombre y migraciones al declarar), `cargarModulo` (cruza la definición con su interruptor de I1 y valida la config con zod) y el esquema del evento que el flujo de entrada entrega a cada módulo. Un stub (`contracts/mod/module.stub.ts`) con un evento de entrada que pasa por el esquema y un flujo de entrada falso con la semántica que MOD.1 debe cumplir. Un archivo de prueba por consumidor (ASG, VIS) y la prueba de verificación del publicador (MOD.1) marcada pendiente con `it.todo`. Ni el publicador (MOD.1) ni los consumidores (ASG.1, VIS.1) se implementan aquí.

**Tech Stack:** TypeScript 6 (strict, target ES2017), zod 4 (`^4.6.7`, dependencia directa ya), vitest 5, Node 22.

**Spec:** `prd-hub` → `prds/wacrm-tenant-repo-template/slices/CT.3-contrato-modulos.md`
(origen `04-modulos#i3`; reglas que lo sostienen: `05-reglas#r16` a `#r20`, y `#r21`, `#r27` por el lado de los consumidores).
Consumidores: `slices/ASG.1-motor-asignacion.md`, `slices/VIS.1-visibilidad-bandeja.md` (los dos con "CDC: las pruebas contra el stub de CT.3 pasan"). Publicador: `slices/MOD.1-mecanismo-modulos.md` ("CDC: la prueba de verificación de CT.3 pasa").

## Review Focus

1. **Módulo apagado con config basura:** no debe tumbar el arranque; R16 dice que apagado no cambia nada (pinned en Tarea 1, `cargarModulo` "no declarado o apagado").
2. **Migración futura de wacrm (`999_*.sql`) frente a una de módulo:** las de módulo deben seguir corriendo después con el glob `/migrations/*.sql` del compose (pinned en Tarea 1, "las de módulos corren después de todas las de wacrm, incluso futuras").
3. **Nombre de módulo con guion o mayúscula (`asig-nacion`, `Asignacion`):** I1 admite guiones, pero el nombre va en `mod_<nombre>_` y en SQL; se rechaza al declarar (pinned en Tarea 1, `definirModulo`).
4. **Enganche que lanza:** el error de un módulo no corta a los demás ni al flujo de entrada (Meta reintenta si el webhook no responde 200) (pinned en Tareas 2 y 3).
5. **Evento con llave de más o id que no es uuid:** el esquema estricto lo rechaza en vez de entregarle al módulo algo a medias (pinned en Tarea 2, "los overrides pasan por el esquema").

## Decisiones tomadas sin Juan

El PRD nombra las cuatro piezas de `I3` (interruptor, migraciones con prefijo propio, esquema zod, punto de enganche) pero no fija nombres, firmas ni semántica. Aquí se fijan; MOD.1, ASG.1 y VIS.1 los heredan:

1. **El interruptor no se redefine:** es el `ModuloSwitch` de I1 (`config/modules.yaml` → `modulos.<nombre>.{activo, config}`). I3 solo le pone esquema a la `config`, que I1 deja opaca (decisión 2 de CT.1).
2. **Nombre de módulo `^[a-z][a-z0-9]*$`:** subconjunto del identificador de I1 sin guiones ni guion bajo, porque el nombre va en el prefijo `mod_<nombre>_` y en SQL, y así el prefijo no es ambiguo.
3. **Migraciones:** `mod_<nombre>_NNN.sql` o `mod_<nombre>_NNN_<descripcion>.sql` en el mismo `supabase/migrations/` (R17 pone de ejemplo `mod_assignment_001.sql`). Corren después de las de wacrm porque el compose las aplica con el glob `/migrations/*.sql` en orden lexicográfico y `m` va después de los dígitos; `ordenMigraciones` deja eso escrito y probado.
4. **Config solo se valida si el módulo está encendido:** apagado o no declarado, `cargarModulo` no mira la config (R16). Encendido e inválido, lanza `ErrorConfigModulo` al arrancar (R18).
5. **Punto de enganche = `alEntrarMensaje(evento, config)`, opcional:** el flujo de entrada lo llama una vez por mensaje entrante **ya guardado** (no por reacciones ni estados de entrega), en orden de declaración, solo para módulos encendidos (R19). VIS no lo usa (R27: solo interfaz). El evento lleva `cuentaId`, `conversacionId`, `contactoId`, `mensajeId`, `asesorAsignadoId` (`null` = sin asesor, lo que dispara ASG por R21), `conversacionNueva` y `recibidoEn`. Los módulos leen y escriben lo demás por datos (R20); el contrato no les pasa un cliente de base.
6. **Un enganche que falla no corta el flujo:** el error se registra y siguen los demás módulos; el mensaje ya quedó guardado y el webhook responde igual a Meta.
7. **`alEntrarMensaje` con sintaxis de método** en `DefinicionModulo`: con propiedad-función, TypeScript estricto no deja meter módulos con config distinta en una misma lista.
8. **"Stub generado":** como en CT.1, no hay generador de código en el repo; el stub está escrito a mano y pasa por `EventoEntradaSchema.parse` y por `cargarModulo`, así que no puede desviarse del contrato sin que fallen sus pruebas.
9. **Esquemas de config en las CDC son ilustrativos:** `reglas` de ASG y `rolesVenTodo` de VIS solo muestran lo que el consumidor espera del mecanismo (defaults aplicados, rechazo de valores inválidos). Sus esquemas reales los fijan ASG.1 y VIS.1.
10. **Se agrega la fila de I3 a `contracts/README.md`** (CT.2 lo creó con solo I2). No se agrega I1: no es de este slice.

**Para confirmar con Juan:** los nombres fijados en 2, 3 y 5 (`mod_<nombre>_NNN[_desc].sql`, `alEntrarMensaje`, campos de `EventoEntrada`) y que el enganche corra solo con mensajes entrantes guardados. Cambiarlos después es un cambio de contrato que arrastra a MOD.1, ASG.1 y VIS.1.

Es el texto del contrato, va literal:

```ts
/**
 * Contrato I3 · Mecanismo de módulos (origen 04-modulos#i3).
 * Publica MOD (MOD.1); consumen ASG y VIS. No lo cambies sin actualizar antes el PRD.
 *
 * Un módulo es: un nombre, un esquema zod de su config, sus migraciones con prefijo
 * propio (R17) y, opcional, un enganche en el flujo de entrada del fork (R19). El
 * interruptor y la config cruda vienen de I1 (`config/modules.yaml`).
 *
 * Convención de contracts/: `<carril>/<nombre>.ts`, `*.stub.ts`,
 * `*.cdc-<consumidor>.test.ts`, `*.publicador.test.ts`.
 */

import { z } from 'zod';
import type { ModuloSwitch } from '../cfg/tenant-config';

export const VERSION_CONTRATO = 'I3.v1';

/** Subconjunto del identificador de I1 sin guiones: el nombre va en `mod_<nombre>_` y en SQL. */
export const NOMBRE_MODULO = /^[a-z][a-z0-9]*$/;

/** `mod_<nombre>_NNN.sql` o `mod_<nombre>_NNN_<descripcion>.sql` (R17). */
export const MIGRACION_MODULO =
  /^mod_([a-z][a-z0-9]*)_(\d{3})(_[a-z0-9_]+)?\.sql$/;

/** Migraciones de wacrm: `NNN_<descripcion>.sql` (supabase/migrations). */
export const MIGRACION_WACRM = /^\d{3}_[a-z0-9_]+\.sql$/;

export function prefijoMigracion(nombre: string): string {
  return `mod_${nombre}_`;
}

export function esMigracionDeModulo(archivo: string, nombre: string): boolean {
  const m = MIGRACION_MODULO.exec(archivo);
  return m !== null && m[1] === nombre;
}

/**
 * Orden en que corren las migraciones: el mismo que el glob `/migrations/*.sql`
 * (orden lexicográfico por byte). Todas las de wacrm quedan antes que las de módulos.
 */
export function ordenMigraciones(archivos: readonly string[]): string[] {
  return [...archivos].sort((a, b) => (a < b ? -1 : a > b ? 1 : 0));
}

/** Lo que el flujo de entrada le pasa a cada módulo encendido, por mensaje entrante ya guardado. */
export const EventoEntradaSchema = z.strictObject({
  cuentaId: z.uuid(),
  conversacionId: z.uuid(),
  contactoId: z.uuid(),
  mensajeId: z.uuid(),
  /** `null` = conversación sin asesor (lo que dispara ASG, R21). */
  asesorAsignadoId: z.uuid().nullable(),
  conversacionNueva: z.boolean(),
  recibidoEn: z.iso.datetime({ offset: true }),
});

export type EventoEntrada = z.infer<typeof EventoEntradaSchema>;

export interface DefinicionModulo<C> {
  nombre: string;
  configSchema: z.ZodType<C>;
  migraciones: readonly string[];
  /** Sintaxis de método a propósito: deja registrar módulos de config distinta en una lista. */
  alEntrarMensaje?(evento: EventoEntrada, config: C): Promise<void>;
}

export type ModuloCargado<C> =
  | { nombre: string; activo: false }
  | {
      nombre: string;
      activo: true;
      config: C;
      alEntrarMensaje?(evento: EventoEntrada, config: C): Promise<void>;
    };

export class ErrorDefinicionModulo extends Error {
  override name = 'ErrorDefinicionModulo';
}

export class ErrorConfigModulo extends Error {
  override name = 'ErrorConfigModulo';
  constructor(
    readonly modulo: string,
    readonly problemas: z.core.$ZodIssue[]
  ) {
    super(
      `config inválida del módulo ${modulo}: ${problemas
        .map((p) => `${p.path.join('.') || '(raíz)'}: ${p.message}`)
        .join('; ')}`
    );
  }
}

/** Valida nombre y migraciones al declarar el módulo; falla al importar, no en producción. */
export function definirModulo<C>(
  def: DefinicionModulo<C>
): DefinicionModulo<C> {
  if (!NOMBRE_MODULO.test(def.nombre)) {
    throw new ErrorDefinicionModulo(`nombre de módulo inválido: ${def.nombre}`);
  }
  for (const archivo of def.migraciones) {
    if (!esMigracionDeModulo(archivo, def.nombre)) {
      throw new ErrorDefinicionModulo(
        `la migración ${archivo} no lleva el prefijo ${prefijoMigracion(def.nombre)}NNN`
      );
    }
  }
  if (new Set(def.migraciones).size !== def.migraciones.length) {
    throw new ErrorDefinicionModulo(`migraciones repetidas en ${def.nombre}`);
  }
  return Object.freeze({
    ...def,
    migraciones: Object.freeze([...def.migraciones]),
  });
}

/**
 * Cruza la definición con su interruptor de I1. Apagado o no declarado: no se valida
 * ni se engancha nada (R16). Encendido: la config pasa por el esquema del módulo y,
 * si no cumple, lanza ErrorConfigModulo (R18: el arranque falla).
 */
export function cargarModulo<C>(
  def: DefinicionModulo<C>,
  interruptor: ModuloSwitch | undefined
): ModuloCargado<C> {
  if (!interruptor?.activo) return { nombre: def.nombre, activo: false };
  const r = def.configSchema.safeParse(interruptor.config);
  if (!r.success) throw new ErrorConfigModulo(def.nombre, r.error.issues);
  return {
    nombre: def.nombre,
    activo: true,
    config: r.data,
    alEntrarMensaje: def.alEntrarMensaje,
  };
}
```

```ts
/**
 * Stub del contrato I3: un evento de entrada que pasa por EventoEntradaSchema.parse y
 * un flujo de entrada falso con la semántica que MOD.1 debe cumplir. Los consumidores
 * (ASG, VIS) prueban contra esto, no contra el webhook real.
 */

import type { ModuloSwitch } from '../cfg/tenant-config';
import {
  EventoEntradaSchema,
  cargarModulo,
  type DefinicionModulo,
  type EventoEntrada,
  type ModuloCargado,
} from './module';

export const IDS_STUB = {
  cuenta: '11111111-1111-4111-8111-111111111111',
  conversacion: '22222222-2222-4222-8222-222222222222',
  contacto: '33333333-3333-4333-8333-333333333333',
  mensaje: '44444444-4444-4444-8444-444444444444',
  asesor: '55555555-5555-4555-8555-555555555555',
} as const;

export function stubEventoEntrada(
  overrides: Partial<Record<keyof EventoEntrada, unknown>> = {}
): EventoEntrada {
  return EventoEntradaSchema.parse({
    cuentaId: IDS_STUB.cuenta,
    conversacionId: IDS_STUB.conversacion,
    contactoId: IDS_STUB.contacto,
    mensajeId: IDS_STUB.mensaje,
    asesorAsignadoId: null,
    conversacionNueva: false,
    recibidoEn: '2026-10-24T15:00:00.000Z',
    ...overrides,
  });
}

export interface ResultadoEntrada {
  ejecutados: string[];
  errores: { modulo: string; error: unknown }[];
}

export interface FlujoEntradaStub {
  cargados: readonly ModuloCargado<unknown>[];
  procesar(evento: EventoEntrada): Promise<ResultadoEntrada>;
}

/**
 * Arranque: carga todos los módulos (una config inválida lanza aquí, R18).
 * Por mensaje: llama en orden de declaración el enganche de cada módulo encendido;
 * el error de un módulo se registra y no corta a los demás ni al flujo de entrada.
 */
export function stubFlujoEntrada(
  modulos: readonly DefinicionModulo<unknown>[],
  interruptores: Record<string, ModuloSwitch> = {}
): FlujoEntradaStub {
  const cargados = modulos.map((def) =>
    cargarModulo(def, interruptores[def.nombre])
  );
  return {
    cargados,
    async procesar(evento) {
      const valido = EventoEntradaSchema.parse(evento);
      const resultado: ResultadoEntrada = { ejecutados: [], errores: [] };
      for (const m of cargados) {
        if (!m.activo || !m.alEntrarMensaje) continue;
        try {
          await m.alEntrarMensaje(valido, m.config);
          resultado.ejecutados.push(m.nombre);
        } catch (error) {
          resultado.errores.push({ modulo: m.nombre, error });
        }
      }
      return resultado;
    },
  };
}
```
